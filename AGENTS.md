# Работа с проектом

## Назначение
- Это учебная копия приложения операторов 112 для подготовки специалистов перед допуском к реальной системе.
- Основной объём: создание карточек инцидентов, изменение их состояния и вывод списка карточек. Не расширяй функционал до полного оригинала без задачи пользователя.
- Сохраняй визуальное сходство с оригиналом: компоновку, плотность форм и таблиц, вкладки, подписи и цвета состояний. Не делай произвольный редизайн.
- `docs/Manual.pdf` — дополнительный справочник по интерфейсу и терминологии, а не точная спецификация бизнес-логики. Исходные процессы неизвестны; опирайся на согласованные требования и текущую реализацию, явно обозначай новые предположения.

## Стек и навигация
- Backend: PHP 8.2+, Laravel 12, Eloquent, Spatie Laravel Permission. Frontend: Vue 3 (Composition API), Inertia 2, Vite, Tailwind CSS.
- Маршруты: `routes/web.php`, `routes/api.php`; карточки: `app/Http/Controllers/IncidentsController.php`, `app/Http/Requests/IncidentRequest.php`, `app/Models/Incident.php`.
- Состояния и переходы: `app/Condition.php`, `app/DepartmentReportCondition.php`, `app/Events/`, `app/Listeners/`, модели `Incident`, `FireReport`, `EddsReport`.
- Форма карточки: `resources/js/Pages/Incidents/Edit.vue` и `Partials/`; список: `resources/js/Pages/Dashboard/Incidents/`; общие компоненты и утилиты: `resources/js/Components/`, `resources/js/Utils/`.
- Роли и права: `database/seeders/RolesAndPermissionsSeeder.php`, `app/Policies/`, `resources/js/Utils/permissions.js`; общие Inertia-данные: `app/Http/Middleware/HandleInertiaRequests.php`.

## Правила изменений
- Развивай существующую реализацию небольшими изменениями; сохраняй русскоязычный интерфейс и принятую терминологию (УКИО, ЕДДС, подразделения 01).
- Учитывай роли `cov_112`, `op_01`, `edds`, территориальную доступность и режимы создания, редактирования и просмотра. Проверки прав должны работать на сервере, а не только скрывать элементы интерфейса.
- При изменении переходов прослеживай всю цепочку: состояние подразделения → отчёт службы → карточка → отображение и фильтры списка. Не меняй числовые значения enum без учёта сохранённых данных и frontend.
- Сохраняй подключение подразделений 01 и связанные данные отчётов. Изменения полей согласовывай между миграциями, моделями, валидацией и Vue-формами.
- Не считай наличие UI или policy доказательством завершённой реализации: проверяй фактическое сохранение, применение прав и обработчики событий.
- Не включай секреты из `.env` в код и вывод; не сбрасывай базу и не перезаписывай пользовательские изменения без явной необходимости и разрешения.

## Проверка
- Для backend-изменений запускай подходящие тесты через `php artisan test`; для frontend — `npm run build`. Для изменений бизнес-логики добавляй проверки затронутых сценариев.
- При изменении карточек проверяй создание, повторное открытие и сохранение, переходы состояний, список и фильтры для затронутых ролей, включая подразделения 01.
- Текущие тесты в основном относятся к авторизации и профилю; их успех сам по себе не подтверждает корректность карточек. Сообщай, что проверено и что осталось непроверенным.
- Для локальной разработки: `php artisan serve` и `npm run dev` в отдельных терминалах; настройка БД и начальные команды описаны в `README.md`.
